# Phase 3 — Decomposition

Fit a generative model for residual updates: per-layer sparse sources plus a depth kernel (or a state-space model, if Gate 2 chose that branch). This is the "central contribution" step — everything before it characterises; this step *builds* something.

**Gate 3.** Is reconstruction quality comparable to SAE / crosscoder baselines on the same activations, with competitive sparsity?

## Step 1 — Lock the architecture based on Gate 2

Read `runs/gate2/phase3_architecture.md` and copy its decision into this phase's top-level README. The three branches:

- **Branch A — Stationary convolutive.** Fit $`\Delta_\ell \approx \sum_{k=0}^{K} W_k s_{\ell-k}`$ where $`\lbrace s_{\ell'}\rbrace_{\ell'=0}^{L-1}`$ are sparse latent vectors at each source layer (convention: $`s_{\ell-k} = 0`$ for $`\ell-k \lt 0`$; one source per residual state that can write into a subsequent update), $`W_k \in \mathbb{R}^{D \times M}`$ is a low-rank kernel at lag $`k`$ shared across all target depths, $`M`$ is the dictionary width (bigger than $`D`$), and $`K`$ is the effective depth $`k^\ast`$ from Phase 2. Branch A requires a **single shared dictionary width $`M`$** across source layers: the kernel $`W_k`$ is one matrix, so its source-side dimension cannot vary with $`\ell'`$. If public per-layer SAEs for the chosen model have different widths across layers, pick a single $`M`$ and retrain (or truncate) the SAEs to match before fitting Branch A — or fall back to Branch B.
- **Branch B — Depth-indexed / state-space.** Fit $`z_{\ell+1} = A_\ell z_\ell + B_\ell u_\ell`$ for $`\ell \in \lbrace 0, \ldots, L-2\rbrace`$ (so the transitions produce states $`z_1, \ldots, z_{L-1}`$ from the initial $`z_0`$; no $`A_{L-1}`$ or $`B_{L-1}`$ are defined because $`z_L`$ is never used), with low-rank $`A_\ell, B_\ell`$ (for $`\ell \in \lbrace 0, \ldots, L-2\rbrace`$) and $`C_\ell, D_\ell`$ (for $`\ell \in \lbrace 0, \ldots, L-1\rbrace`$) — same rank sweep $`r \in \lbrace 16, 32, 64, 128\rbrace`$ as Branch A's $`W_k`$; enforce rank per-matrix via factorisation $`A_\ell = A_\ell^{(1)} (A_\ell^{(2)})^\top`$ and analogously for $`B_\ell, C_\ell, D_\ell`$, where $`z_\ell`$ is the SSM latent state. The observation model decodes the state into the residual update **with a direct feedthrough from the current-layer input**: $`\Delta_\ell \approx b_\ell + C_\ell z_\ell + D_\ell u_\ell`$. The feedthrough term $`D_\ell u_\ell`$ keeps Branch B structurally analogous to Branch A's $`k=0`$ tap $`W_0 s_\ell`$ — without it, $`z_\ell = A_{\ell-1} z_{\ell-1} + B_{\ell-1} u_{\ell-1}`$ depends only on inputs $`u_{0:\ell-1}`$, and Branch B would be a strictly weaker predictor than Branch A by one lag. $`D_\ell`$ specifically is the direct Branch-B analogue of Branch A's $`W_0`$ (both map $`\mathbb{R}^M \to \mathbb{R}^D`$ at the same layer), which is why the rank constraint on $`D_\ell`$ matches $`W_0`$'s. The per-layer bias $`b_\ell`$ has the same role and motivation as in Branch A (absorbs $`\bar\Delta_\ell`$, sits outside the kernel parameterisation). The initial state $`z_0`$ is learned as a free parameter or fixed at zero — the choice matters only for the first few layers and is recorded in the Gate 3 memo. **Symbol note (state $`z_\ell`$ vs sources $`s_{\ell'}`$).** The canonical SSM literature writes the state as $`s_\ell`$; this proposal writes it as $`z_\ell`$ to avoid collision with the Branch A sources $`\lbrace s_{\ell'}\rbrace`$ (per-layer SAE latents, defined in Step 2), which are a different object — sparse codes living in a dictionary space per layer, not an evolving latent state. The inputs $`u_\ell`$ into the Branch B state update can be initialised from the same per-layer SAE latents as Branch A's sources; the two objects play different structural roles even when they share an initialisation. **Symbol note (matrix $`D_\ell`$ vs dimension $`D`$).** The SSM feedthrough matrix $`D_\ell`$ shares its capital letter with the residual-stream dimension $`D`$ used throughout this plan (e.g. in $`W_k \in \mathbb{R}^{D \times M}`$ and the $`2D`$ term of the parameter count below); they are distinguished only by the subscript. Read $`D_\ell`$ (subscripted) as the layer $`\ell`$ feedthrough matrix and bare $`D`$ as the residual-dimension scalar. I keep the canonical SSM letter rather than renaming because $`D`$ for feedthrough is universal in control theory and renaming it would be more disorienting than the collision is — but every use of bare $`D`$ in Branch B is a scalar, and every $`D_\ell`$ is a matrix.
- **Branch C — Segmented.** Same as Branch A within each segment (early / middle / late or whatever boundaries Gate 2 identified), with separate kernels per segment.

The rest of Phase 3 describes Branch A in detail. Branch C inherits Branch A's optimisation procedure (same alternating pattern, same closed-form kernel update within each segment), sparsity regime, and sanity checks directly. Branch B inherits the **alternating pattern** (input update vs. parameter update) and the sparsity regime (L1 on per-layer inputs) but *not* the closed-form kernel update: because $`z_\ell = \left(\prod_{j\lt\ell} A_j\right) z_0 + \sum_{j\lt\ell} \left(\prod_{j\lt k\lt\ell} A_k\right) B_j u_{j}`$ is polynomial in $`\lbrace A_\ell, B_\ell\rbrace`$ (**product-ordering convention:** every $`\prod`$ in this Branch B section unrolls in *decreasing*-index left-to-right order to match the SSM forward chain — $`\prod_{j\lt\ell} A_j \equiv A_{\ell-1} A_{\ell-2} \cdots A_{0}`$ and $`\prod_{j\lt k\lt\ell} A_k \equiv A_{\ell-1} A_{\ell-2} \cdots A_{j+1}`$, with the empty product equal to the identity; the standard `\prod_{k=a}^{b}` convention is the reverse order, and applying that here gives the wrong matrix because matrix multiplication does not commute, so always read $`\prod`$ in this section as decreasing-index), the Branch B parameter update — i.e. the step that fixes $`\lbrace u_\ell\rbrace`$ and solves for $`\lbrace A_\ell, B_\ell, C_\ell, D_\ell, b_\ell, z_0\rbrace`$ — is not a ridge problem; run gradient descent on $`\mathcal{L}_{B}`$ via autodiff (Adam, same $`\lambda_{L1}`$ and $`\lambda_{\text{reg}}`$ as Branch A), unrolling the SSM through all $`L`$ layers in the forward pass. The alternation is preserved: one Adam sweep over parameters with $`\lbrace u_\ell\rbrace`$ held fixed, then one proximal-gradient pass over inputs with parameters held fixed — do **not** co-optimise all variables in a single Adam call, because that collapses the alternation and loses the LASSO's sparsity guarantees on $`\lbrace u_\ell\rbrace`$. The Branch B input update uses the same unrolled expression for $`\hat\Delta_\ell`$ as an explicit linear function of the stacked $`(u_0, \ldots, u_{L-1})^{(i)}`$: with parameters fixed, $`\hat\Delta_\ell - b_\ell - C_\ell (\prod A) z_{0}`$ is a linear function of the stacked inputs alone, and the Branch B input update is a single coupled LASSO on the stacked $`(u_0, \ldots, u_{L-1})^{(i)}`$ per example solved via proximal-gradient descent — one LASSO per example, coupled across all depths because $`u_{j}`$ enters $`\hat\Delta_\ell`$ for every $`\ell \ge j`$ through both the feedthrough and the state chain. The sanity checks in [Step 4](#step-4--sanity-checks-before-gate-3) apply to both branches with the variable substitutions flagged inline. For Branch B specifically, the sparsity regime attaches to the per-layer inputs $`\lbrace u_\ell^{(i)}\rbrace`$ in direct parallel to Branch A's sources, and the consolidated Branch B loss (matching the Branch A form in [Step 3](#step-3--loss-and-optimisation-branch-a--c)) is

$$\mathcal{L}_{B}(\lbrace u_\ell\rbrace, \lbrace z_0, b_\ell, A_\ell, B_\ell, C_\ell, D_\ell\rbrace) = \sum_{i=1}^N \sum_{\ell=0}^{L-1} \left\| \Delta_\ell^{(i)} - b_\ell - C_\ell z_\ell^{(i)} - D_\ell u_\ell^{(i)} \right\|^2 + \lambda_{L1} \sum_{i=1}^N \sum_{\ell=0}^{L-1} \|u_\ell^{(i)}\|_1 + \lambda_{\text{reg}} \left[ \sum_{\ell=0}^{L-2} \left( \|A_\ell\|_F^2 + \|B_\ell\|_F^2 \right) + \sum_{\ell=0}^{L-1} \left( \|C_\ell\|_F^2 + \|D_\ell\|_F^2 \right) \right]$$

subject to the SSM dynamics $`z_{\ell+1}^{(i)} = A_\ell z_\ell^{(i)} + B_\ell u_\ell^{(i)}`$ for $`\ell = 0, \ldots, L-2`$, with $`z_0`$ either a free learned parameter or fixed at zero. The $`\lambda_{L1}`$ sweep and $`\lambda_{\text{reg}}`$ pin are the same as Branch A; $`b_\ell`$ and $`z_0`$ are unpenalised (nuisance parameters, not features).

## Step 2 — Define sparse source representations $`\lbrace s_{\ell'}\rbrace`$

**Question.** What are the "sources" that the depth kernel convolves?

**Decision:** initialise $`\lbrace s_{\ell'}\rbrace_{\ell'=0}^{L-1}`$ as per-layer [sparse autoencoder](../glossary.md#sae) latents — at every source layer $`\ell' \in \lbrace 0, 1, \ldots, L-1\rbrace`$, the source vector $`s_{\ell'}`$ is the latent representation of the layer $`\ell'`$ residual stream activation ($`v_{\ell'}`$) under a standard SAE trained on that layer. One source per residual state that can write into a subsequent update; $`v_L`$ is the final state and has no downstream update to contribute to, so no $`s_L`$ is defined. Where public per-layer SAEs exist for Pythia-410m (Pythia SAE checkpoints / SAELens), use them. Otherwise, train minimal per-layer SAEs — still the cheapest thing in the whole pipeline, a few hours on one GPU per layer, and embarrassingly parallel across layers.

This is a choice with real tradeoffs:
- **Pro:** every $`s_{\ell'}`$ is interpretable from the start because SAE latents are; the decomposition inherits this interpretability.
- **Con:** SAE initialisation biases the alternating-minimisation trajectory toward the SAE-discovered subspace at each layer. The LASSO source update in [Step 3](#step-3--loss-and-optimisation-branch-a--c) leaves the sources free to drift, but starting from SAE encodings means features SAE misses at a given layer are unlikely to be surfaced spontaneously.
- **Alternative:** treat $`\lbrace s_{\ell'}\rbrace`$ as free parameters, initialise randomly, and learn them jointly with the kernel. I will not do this first — too many free parameters, unclear optimisation landscape. If the SAE-initialised version fits poorly, try this as an ablation.
- **Embedding-only ablation.** A simplified variant with sources only at $`s_0`$ (all $`s_{\ell'} = 0`$ for $`\ell' \gt 0`$) is reported as a lower bound; per [proposal §4.3](../README.md#43-where-the-emg-intuition-sits--and-where-it-stops) it is expected to under-fit late-layer updates.

**Width.** Match the public SAE's width, typically $`M = 8D`$ or $`M = 16D`$. Under Branch A (stationary convolutive) the same width **must** be used at every layer, because $`W_k`$ is a single matrix shared across source positions and cannot absorb source-side dimension mismatches. If the public SAE suite uses layer-varying widths, pick one $`M`$ and retrain (or truncate) so all layers match before Branch A fitting. **Branch B (state-space)** can accommodate per-layer $`M_{\ell'}`$ because its per-depth operators $`A_\ell, B_\ell, C_\ell, D_\ell`$ are free to have different source-side shapes; the depth-smoothed Branch B variant from [Step 3](#step-3--loss-and-optimisation-branch-a--c) loses that freedom, however, because linear factor interpolation between $`L_c`$ control depths requires the rank $`r`$ factors of $`B_\ell`$ (and $`D_\ell`$) to share shapes, so the smoothed variant inherits Branch A's single $`M`$ requirement. **Branch C (segmented)** accommodates only **per-segment** $`M^{(\text{seg})}`$, not per-layer: within a segment the kernel $`\lbrace W_k^{(\text{seg})}\rbrace`$ is shared, so all source layers in that segment must share dictionary width — Branch A's constraint scoped down to a segment, not removed. So on Pythia-410m a Branch C decomposition tolerates up to three distinct $`M`$ values across the early/middle/late segments, but cannot vary $`M_{\ell'}`$ within a single segment.

## Step 3 — Loss and optimisation (Branch A / C)

> **Branch B readers:** the Branch B loss and optimisation recipe live in [Step 1's consolidation paragraph](#step-1--lock-the-architecture-based-on-gate-2) — the Adam-over-parameters / proximal-gradient-LASSO-over-inputs alternation, not the Branch A outer loop below. Come back here only for the hyperparameter sweep (which $`\lambda_{L1}`$ and $`\lambda_{\text{reg}}`$ values are reused, which are Branch-A-only) and for the cross-reference from Step 4's sanity checks.

**Loss function.**

$$\mathcal{L}(\lbrace s_{\ell'}\rbrace, \lbrace b_\ell \rbrace, W_{0:K}) = \sum_{i=1}^N \sum_{\ell=0}^{L-1} \left\| \Delta_\ell^{(i)} - b_\ell - \sum_{k=0}^K W_k \, s_{\ell-k}^{(i)} \right\|^2 + \lambda_{L1} \sum_{i=1}^N \sum_{\ell'=0}^{L-1} \|s_{\ell'}^{(i)}\|_1 + \lambda_{\text{reg}} \sum_{k=0}^K \|W_k\|_F^2$$

with the convention $`s_{\ell-k}^{(i)} = 0`$ for $`\ell-k \lt 0`$.

- Reconstruction MSE across depths $`\ell`$ and examples $`i`$.
- Per-layer bias $`b_\ell \in \mathbb{R}^D`$ absorbs the layer-wise mean $`\bar\Delta_\ell`$. Without it the L1 penalty drives source means toward zero, and the model cannot fit $`\bar\Delta_\ell \ne 0`$ cleanly. The bias is fit jointly (see the kernel-update step below); it lives outside the kernel parameterisation and therefore does not affect H2's stationarity claim on $`\lbrace W_k\rbrace`$, which is a claim about the transition structure and not about layer-wise offsets.
- [L1 penalty](../glossary.md#l1) on every $`s_{\ell'}^{(i)}`$ drives sparse source activations at each layer; the bias $`b_\ell`$ is *not* L1-penalised (it is a nuisance parameter, not a feature).
- Frobenius regulariser on the kernels to prevent collapse.

**Optimisation: [alternating minimization](../glossary.md#alternating-minimization).**

*Outer loop* (until convergence or max iterations):
1. **Source update.** Fix $`W_{0:K}`$ and $`\lbrace b_\ell \rbrace`$, solve for the stacked source vector $`(s_0, s_1, \ldots, s_{L-1})^{(i)}`$ per example. Because $`s_{\ell'}^{(i)}`$ contributes to the prediction of $`\Delta_\ell^{(i)}`$ for $`\ell \in \lbrace \ell', \ell'+1, \ldots, \min(\ell'+K, L-1)\rbrace`$, the per-example problem is a single joint LASSO — one sparse optimisation over the stacked sources against the stacked targets $`(\Delta_0 - b_0, \Delta_1 - b_1, \ldots, \Delta_{L-1} - b_{L-1})^{(i)}`$ (bias-subtracted because $`b_\ell`$ is held fixed here), not one-per-layer. Use `scikit-learn`'s `Lasso` or, for speed on GPU, a proximal-gradient step in PyTorch.
2. **Kernel update.** Fix all $`\lbrace s_{\ell'}^{(i)}\rbrace`$, solve for $`W_{0:K}`$ and $`\lbrace b_\ell \rbrace`$ jointly. With the Frobenius penalty on kernels, unpenalised per-layer biases, and *no* rank constraint, this is closed-form ridge regression: stack lagged source vectors across examples and depths as regressors, append one-hot depth-indicator columns for the biases, and solve the combined system with the Frobenius penalty applied only to the source-coefficient block (not to the bias columns). Do **not** use the shortcut "mean-centre $`\Delta_\ell`$ per depth and fit without biases" — since SAE-initialised sources have non-zero means, that shortcut yields a different $`W_k`$ than the joint fit (intercept-as-mean-centre equivalence requires mean-centring the regressors too, and the same $`s_{\ell'}`$ appears at multiple target depths, which makes source mean-centring awkward to define). The rank $`r`$ constraint on each $`W_k`$ is not simultaneously closed-form — follow the same trick as [Phase 1 Step 3](phase-1-diagnostic.md#step-3--linear-depth-local-predictability-h1-weak-form): solve the full-rank ridge first, then truncate each $`W_k`$ by SVD to rank $`r`$. Fall back to direct alternating low-rank factorisation only if the SVD-truncated solution fits materially worse than the full-rank one.
3. Log reconstruction MSE and the L0 count of $`\lbrace s_{\ell'}\rbrace`$ (fraction of nonzeros across all layers).

**Hyperparameter sweep.**
- $`\lambda_{L1} \in \lbrace 10^{-4}, 10^{-3}, 10^{-2}, 10^{-1}\rbrace`$ — to generate a sparsity–reconstruction Pareto curve.
- $`\lambda_{\text{reg}}`$ (Frobenius penalty on $`\lbrace W_k\rbrace`$): fix at $`10^{-4}`$ for the main run (a conservative ridge floor that stabilises the kernel update without materially biasing reconstruction). Re-tune only if the kernel norms drift during alternating minimisation — if $`\max_k \|W_k\|_F`$ grows by more than ~50% across outer iterations, raise $`\lambda_{\text{reg}}`$ by a decade and rerun; if the SVD-truncated $`W_k`$ recovers noticeably worse than the full-rank fit, lower $`\lambda_{\text{reg}}`$ by a decade. Record the final value in the Gate 3 memo.
- Kernel rank $`r \in \lbrace 16, 32, 64, 128\rbrace`$ per $`W_k`$.
- Kernel length $`K`$ fixed to the effective depth $`k^\ast`$ from [Phase 2 Step 2](phase-2-characterization.md#step-2--effective-kernel-depth); do not retune. **Indexing note.** Phase 2's $`k^\ast`$ is the order of an AR model on $`\Delta`$ with lags $`j \in \lbrace 1, \ldots, k^\ast \rbrace`$ — $`k^\ast`$ past $`\Delta`$ lags, by construction excluding the current $`\Delta_\ell`$ to avoid tautology. The convolutive model here uses lags $`k \in \lbrace 0, 1, \ldots, K \rbrace`$ over the *sources* $`s_{\ell-k}`$, giving $`K+1`$ taps; the $`k=0`$ tap maps the current-layer source $`s_\ell`$ (an SAE latent of $`v_\ell`$, not of $`\Delta_\ell`$) and is therefore not tautological. Setting $`K = k^\ast`$ makes the maximum backward reach into the source history equal to the AR's maximum backward reach into the $`\Delta`$ history, at the cost of one extra (current-layer) tap with no AR analogue. If reconstruction is poor at $`K = k^\ast`$, try $`K = k^\ast - 1`$ as the only alternative considered before falling back to a longer sweep. **Branch B caveat.** $`K`$ is a Branch-A/C hyperparameter; Branch B (state-space) has no kernel length. The Branch B hyperparameters are the SSM latent-state dimension $`d_z`$ and — crucially — a **depth-smoothing budget** on the per-layer operators. Without smoothing, Branch B's parameter count at rank $`r`$ is $`(L-1) \cdot r \cdot (3 d_z + M) + L \cdot r \cdot (2D + M + d_z) = L \cdot r \cdot (4 d_z + 2M + 2D) - r \cdot (3 d_z + M)`$, i.e. $`L \cdot r \cdot (4 d_z + 2M + 2D)`$ to within an $`\mathcal{O}(1/L)`$ correction from the asymmetric indexing ($`A_\ell, B_\ell`$ are defined only for $`\ell \in \lbrace 0, \ldots, L-2\rbrace`$ while $`C_\ell, D_\ell`$ are defined for $`\ell \in \lbrace 0, \ldots, L-1\rbrace`$). This is strictly larger than Branch A's $`(K+1) \cdot r \cdot (D+M)`$ for typical $`(L, K, M, D)`$ because the dominant $`2L(M+D)`$ term does not shrink with $`d_z`$. Matching Branch A's parameter budget by choosing $`d_z`$ alone is mathematically impossible; instead, store the **rank-$`r`$ factors** of $`A_\ell, B_\ell, C_\ell, D_\ell`$ (the $`A_\ell^{(1)}, A_\ell^{(2)}`$ pair and analogues for $`B, C, D`$) at $`L_c \ll L`$ control depths and linearly interpolate the factors between control depths — not the full matrices, because a linear combination of two rank-$`r`$ matrices generally has rank up to $`2r`$, which would break the rank-$`r`$ constraint. Factor-level interpolation preserves rank-$`r`$ exactly. The resulting parameter count is $`L_c \cdot r \cdot (4 d_z + 2M + 2D)`$. Pick $`L_c \approx (K+1)(D+M)/(4 d_z + 2M + 2D)`$ to match Branch A's budget at the same rank $`r`$ (typically $`L_c = 3`$ to $`5`$), with $`d_z`$ on the same order as $`r`$. Do not sweep $`K`$ under Branch B. If the Gate-2 decision-matrix output makes depth-smoothing inappropriate — a clean phase transition would favour Branch C, not smoothly-varying Branch B, and in that case Branch B wouldn't have been selected — drop the parameter-match criterion and report Branch A's and Branch B's parameter counts separately in the Gate 3 memo, so a Branch-B reconstruction win against a materially larger model is not silently equated with a parsimony win.

**Scale plan.**
- **Debug pass:** Pythia-70m ($`D=512`$, $`L=6`$). The whole decomposition fits in memory trivially and an alternating-minimization iteration takes seconds. Use it to shake out bugs in the optimiser before scaling.
- **Primary run:** Pythia-410m. Full pipeline.
- **Optional:** Gemma-2-2B. Only if Pythia-410m produces interesting features and compute is available.

## Step 4 — Sanity checks before Gate 3

Run all of these before writing the Gate 3 memo. Skipping them means trusting reconstruction numbers that might be optimised against the wrong thing.

1. **Trivial solutions.** Does the optimiser collapse to $`\lbrace s_{\ell'}\rbrace = 0`$ and $`W_k = 0`$ with $`\lbrace b_\ell\rbrace`$ absorbing everything into the per-layer mean (the mean-prediction baseline from Phase 1 Step 3)? (It shouldn't, but confirm by logging the norms of sources, kernels, *and* biases during training — a large $`\|b_\ell\|`$ paired with small $`\|W_k\|`$ is the tell for this degenerate solution.) **Branch B variant.** Check the corresponding collapse $`\lbrace u_\ell\rbrace = 0`$ and $`A_\ell = B_\ell = C_\ell = D_\ell = 0`$ with $`\lbrace b_\ell\rbrace`$ again absorbing the mean; log $`\|u_\ell\|_1`$, $`\|A_\ell\|_F, \|B_\ell\|_F, \|C_\ell\|_F, \|D_\ell\|_F`$, and $`\|b_\ell\|`$ during training, and flag the same biases-absorb-everything pattern.
2. **Reconstruction sanity.** For 10 random examples, plot the predicted vs. actual $`\Delta_\ell`$ at every layer. Eyeballing is cheap and catches catastrophic bugs that metrics miss.
3. **Feature activations have expected structure.** Pick 20 of the top features (Branch A/C: largest summed $`|s_{\ell'}|`$ across examples and layers, with the home layer $`\ell'`$ where they live; Branch B: largest summed $`|u_\ell|`$ coordinate-wise across examples and layers, with the home layer $`\ell^*`$). For each, examine the 10 examples where it activates most strongly. Do the subject-relation pairs have a consistent theme? This is a standard feature-interpretability check.
4. **Seed stability.** Rerun the whole pipeline with 3 different random seeds (for the SAE init and the optimiser). Compute feature-matching scores (max cosine similarity of decoder directions) across seeds. Any feature that doesn't match across seeds is suspicious and should not be in the headline evaluation.
5. **Dataset stability.** Retrain on two disjoint halves of the dataset. Do the top features overlap?
6. **MA-stationarity recheck (Branch A only).** [Phase 2 Step 1](phase-2-characterization.md#step-1--stationarity-test) flagged that AR on $`\Delta`$ stationarity is a proxy for the MA-form stationarity H2 actually asserts, and committed to a direct recheck here. Refit Branch A with the kernel constrained to be depth-dependent — a separate $`\lbrace W_k^{(\text{band})}\rbrace`$ per early/middle/late band, same boundaries as Phase 2 — and compare reconstruction MSE and kernel Frobenius distance to the shared-kernel fit. If the per-band fit is materially better or the per-band kernels differ by more than the seed-stability noise floor (from item 4), H2 is not supported in the generative form even if the Phase 2 AR proxy accepted it; record this and flag it in the Gate 3 memo.

If any of these raise a red flag, stop and debug before Gate 3.

## Step 5 — Gate 3 decision

Write a Gate 3 memo answering:

1. **What fraction of variance in $`\Delta_\ell`$ does the decomposition reconstruct**, averaged over layers, at each $`\lambda_{L1}`$ on the Pareto curve?
2. **How does this compare to a per-layer SAE** trained on the same activations with the same L0 sparsity?
3. **How does it compare to a crosscoder baseline**, if one is trainable on the budget?
4. **Are the recovered features seed- and dataset-stable?**
5. **Do any of the top features look interpretable on the "examples that activate them" check?**

**Go criterion for Phase 4:** reconstruction is on or above the per-layer SAE Pareto curve at comparable sparsity, *and* seed stability is above some threshold (e.g. ≥ 0.7 feature-matching across seeds for the top-100 features).

**No-go branches:**
- If reconstruction is much worse than per-layer SAE: the decomposition is under-expressive. Try rank increase, longer kernel, or relax the block-Toeplitz constraint (Branch C instead of A). Only one round of such retuning; do not loop forever.
- If reconstruction is fine but seed stability is terrible: the loss landscape has many equivalent minima. Add stronger regularisation or a dictionary-alignment constraint across seeds. Record this as a limitation.
- If both fail: Phase 3 is the point where the project pivots to writing up the characterisation (Phase 1 + Phase 2 results) as the paper, with the decomposition as a discussion/future-work section.

**Deliverable artefacts at Gate 3:**
- `runs/gate3/memo.md`
- `runs/gate3/figures/` — Pareto curves against baselines, reconstruction plots, seed-stability matrices.
- `runs/gate3/checkpoints/` — the trained decomposition, ready for Phase 4 ablation work.
